# 五个地形对照组实验：租机操作指南

> 目标：在 BH_high / SF_high / USGS_CO / USGS_WA 四张地形上，补齐与 EP_high 同协议的
> 对照组（A1/A2/A3 消融 + GeGnn/NeuroGF/LiteGE 三种论文方法 × native/euclidean_residual），
> 与归档中已有的我方完整方法（M0）在**同一批 5000 对 test 点**上比较。
>
> 前置：代码分支 `five-terrain-controls` 已支持「固定划分读入」；
> 归档数据 `五个地形实验_标签数据与结果_20261024/`（约 1.3 GB）在本地，需单独传到服务器。

---

## 0. 先想清楚要跑什么

每张地形 9 次训练（M0 已有结果，A4 纯直线不用训练）：

| 配置 | architecture | prediction_mode | 说明 |
|---|---|---|---|
| M0（已有） | three_stage | euclidean_residual | 归档里已有 test 数字与 .pt |
| A1 | three_stage | direct | 去欧氏残差 |
| A2 | single_gnn | euclidean_residual | 去分区+highway |
| A3 | single_gnn | direct | 两项都去掉 |
| GeGnn ×2 | gegnn | native / euclidean_residual | 论文方法 |
| NeuroGF ×2 | neurogf | native / euclidean_residual | 论文方法 |
| LiteGE ×2 | litege | native / euclidean_residual | 论文方法 |

统一超参（与归档 M0 一致）：seed=42、100 轮、huber、hidden_dim=64、out_dim=32、
highway_k=3、transit_k=8、batch_size=16、plateau 调度（patience=5, factor=0.5）、
`EUCLID_RESIDUAL_SCALE=1.0`。

**LA（1600 万顶点）当前代码跑不动，本指南不含 LA。**

## 1. 租机器：配置建议

| 项目 | 最低 | 建议 |
|---|---|---|
| GPU | RTX 4090 24GB | A100 40GB（GeGnn 在 256 万顶点图上更稳） |
| CPU | 8 核 | 16 核（预处理采样吃并行） |
| 内存 | 64 GB | 90–128 GB |
| 硬盘 | 100 GB | 200 GB NVMe（高速上下文缓存每张图几 GB） |
| 镜像 | PyTorch 2.x + CUDA 11.8/12.1（AutoDL 官方镜像即可） | 同左 |

平台任选（AutoDL / 趋动云 / 恒源云等）。**先按量租一张 4090 跑通 BH_high 全流程，
确认无误再决定要不要长时间租或升级。**

时间预估（参考归档 M0 的 100 轮耗时）：BH_high ≈ 3.5 h/配置，SF_high ≈ 4.7 h，
USGS_CO/WA ≈ 5.2 h。NeuroGF/LiteGE 是逐点 MLP，会明显更快；GeGnn 更慢且吃显存。
单张图 9 个配置大约 1.5–2 天，四张图建议排队跑，或同时租 2 台分摊。

## 2. 获取数据（两种方式，推荐 A）

归档数据已随分支发布：

- **小文件**（标签、划分、配置、日志、模型 checkpoint、汇总）已直接入库，
  `git clone -b five-terrain-controls` 后就在 `五个地形实验_标签数据与结果_20261024/` 里；
- **大文件**（4 张 `.off` 原始地形 + LA 高程 `.npy`，共约 705MB）超过 git 单文件
  100MB 限制，打包在 Release 资产 `five_terrain_data_20261024.zip`（217MB，完整归档）里。


> 若服务器上 GitHub 下载慢/不通，可改用镜像前缀（如 `https://ghproxy.com/` 类加速），
> 或退到方式 B。

## 6. 第一个训练：BH_high 的 A1

```bash
cd /root/gnn-highewaynetwork-oracle
mkdir -p logs
export EUCLID_RESIDUAL_SCALE=1.0
D=/root/terrain_data/BH_high

python -u main.py \
  --off_file $D/原始地形/BH_high.off --file_folder / \
  --labels_file $D/标签与划分/labels.csv --labels_col true_distance \
  --train_pairs_file $D/标签与划分/train_pairs.csv \
  --val_pairs_file   $D/标签与划分/val_pairs.csv \
  --test_pairs_file  $D/标签与划分/test_pairs.csv \
  --architecture three_stage --prediction_mode direct \
  --loss_type huber --hidden_dim 64 --out_dim 32 \
  --highway_k 3 --transit_k 8 --batch_size 16 \
  --num_epoch 100 --early_stop_patience 100 \
  --lr_scheduler plateau --lr_patience 5 --lr_factor 0.5 \
  --seed 42 --device cuda \
  --run_tag A1_no_res_s42_100ep \
  2>&1 | tee logs/BH_high_A1_no_res_s42_100ep.log
```

注意点：

- `--file_folder /`：因为 `--off_file` 给的是绝对路径，这样写避免再拼一次项目根。
- **首次运行要构建四叉树分区 + 高速骨架 + nearest-k 缓存**，BH_high 约几十分钟，
  之后同一张图的其余 8 个配置直接读 `outputs/cache/`，预处理基本免费。
- 跑起来后日志里应看到
  `[distance] 固定划分（跳过随机切分）：train=40000, val=5000, test=5000`，
  看不到这行就说明固定划分没生效，立即停掉查参数。
- 训练结束看 `outputs/results/BH_high_A1_no_res_s42_100ep.txt`，
  对照实验导出的 `..._test_pairs.csv` 应与归档 test_pairs.csv 内容一致（可用 `diff` 抽查）。

预期结果量级：A1 的 test MRE 应**差于** M0 的 0.903%（EP_high 上同项劣化约 1.34 倍）。
如果反而更好或差到离谱，先检查 `EUCLID_RESIDUAL_SCALE` 和标签列名。

## 7. 批量跑完一张图

存为 `run_one_terrain.sh`（按 BH_high 写好，换 `DS=` 即可复用）：

```bash
#!/bin/bash
set -u
export EUCLID_RESIDUAL_SCALE=1.0
DS=${DS:-BH_high}
D=/root/terrain_data/$DS
cd /root/gnn-highewaynetwork-oracle
mkdir -p logs

COMMON="--off_file $D/原始地形/$DS.off --file_folder / \
  --labels_file $D/标签与划分/labels.csv --labels_col true_distance \
  --train_pairs_file $D/标签与划分/train_pairs.csv \
  --val_pairs_file $D/标签与划分/val_pairs.csv \
  --test_pairs_file $D/标签与划分/test_pairs.csv \
  --loss_type huber --hidden_dim 64 --out_dim 32 \
  --highway_k 3 --transit_k 8 --batch_size 16 \
  --num_epoch 100 --early_stop_patience 100 \
  --lr_scheduler plateau --lr_patience 5 --lr_factor 0.5 \
  --seed 42 --device cuda"

run() {  # $1=run_tag, 其余=追加参数
  tag=$1; shift
  echo "=== $DS $tag ==="
  python -u main.py $COMMON "$@" --run_tag "$tag" 2>&1 | tee "logs/${DS}_${tag}.log"
}

run A1_no_res_s42_100ep        --architecture three_stage --prediction_mode direct
run A2_single_res_s42_100ep    --architecture single_gnn  --prediction_mode euclidean_residual
run A3_single_direct_s42_100ep --architecture single_gnn  --prediction_mode direct
run GeGnn_native_s42_100ep     --architecture gegnn       --prediction_mode native            --grad_clip 1.0
run GeGnn_res_s42_100ep        --architecture gegnn       --prediction_mode euclidean_residual --grad_clip 1.0
run NeuroGF_native_s42_100ep   --architecture neurogf     --prediction_mode native
run NeuroGF_res_s42_100ep      --architecture neurogf     --prediction_mode euclidean_residual
run LiteGE_native_s42_100ep    --architecture litege      --prediction_mode native
run LiteGE_res_s42_100ep       --architecture litege      --prediction_mode euclidean_residual
echo "ALL DONE $DS"
```

用法：

```bash
chmod +x run_one_terrain.sh
DS=BH_high  nohup ./run_one_terrain.sh > logs/BH_high_all.out 2>&1 &
DS=SF_high  nohup ./run_one_terrain.sh > logs/SF_high_all.out 2>&1 &   # 另一台机器或排队
```

建议：**先只放开 A1 一行跑通，再放开其余行**。`single_gnn` 与三种 baseline
不构建高速上下文，预处理快很多。

## 8. 产物位置与回收

每次训练产出（仓库根下）：

```
outputs/models/<DS>_<tag>.pt              # 权重
outputs/results/<DS>_<tag>.txt            # 汇总指标（test_mae / test_rmse / test_relative_error / 分组）
outputs/results/<DS>_<tag>_test_pairs.csv # 应与归档 test_pairs.csv 一致
outputs/params/<DS>_<tag>.txt             # 全部运行参数
```

跑完一张图，抽指标汇总：

```bash
python - <<'EOF'
import glob, os
rows = []
for p in sorted(glob.glob('outputs/results/*_s42_100ep.txt')):
    kv = dict(l.split(None, 1) for l in open(p) if ' ' in l)
    name = os.path.basename(p)[:-4]
    rows.append((name, kv.get('architecture','?'), kv.get('prediction_mode','?'),
                 float(kv['test_relative_error'])*100, float(kv['test_mae']), float(kv['test_rmse'])))
print('run,architecture,prediction_mode,test_MRE%,MAE,RMSE')
for r in rows:
    print(','.join(map(str, r)))
EOF
```

回收（在本地执行）：

```bash
scp -r -P <端口> root@<主机>:/root/gnn-highewaynetwork-oracle/outputs/results ./云端结果_results
scp -r -P <端口> root@<主机>:/root/gnn-highewaynetwork-oracle/logs          ./云端结果_logs
# 模型 .pt 每个仅约 180 KB，也建议拉回：
scp -r -P <端口> root@<主机>:/root/gnn-highewaynetwork-oracle/outputs/models ./云端结果_models
```

`outputs/cache/` 是预处理缓存，**不要**往回拉；但服务器上别删，重跑能省几十分钟。

## 9. 常见问题

1. **GeGnn 显存 OOM**：先用 `--grad_clip 1.0`（脚本里已加）；仍 OOM 则 GeGnn 需要
   梯度检查点补丁（当前分支未包含，EP_high 对照工程里有参考实现），
   可先把 GeGnn 两行注释掉，跑完其余 7 个配置再单独处理。
2. **NeuroGF native 不收敛属预期**：EP_high 上其 native 输出 MRE 0.52，本来就差；
   记录数字即可，不要为它调参，保持协议一致。
3. **LA 跑不了**：1600 万顶点全图前向超出当前实现能力（归档 M0 用了服务器上的
   专门加速，未入库）。LA 只做 A4（第 5 节脚本换个路径即可算）和留待后续。
4. **中文路径报错**：极少见，若某个工具不认中文，把 `terrain_data/<DS>/标签与划分`
   等目录改名/软链为英文并同步改脚本路径。
5. **USGS .off 第三行是 0**：OFF 的边数列本来就可写 0，加载器按面重建边，不影响。
6. **多任务并行拖慢**：同机多开训练时加 `--torch_threads 4` 之类限制线程数。
7. **断点**：`main.py` 不支持续训；中断的 run 删掉对应产物重跑即可
   （预处理缓存还在，重跑代价主要是训练时间）。
